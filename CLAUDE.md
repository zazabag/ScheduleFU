# Контекст проекта ScheduleFU

Этот файл читается Claude Code автоматически при работе в этой папке.

## Что это за проект

ScheduleFU — сервис отображения свободных аудиторий Финансового
университета при Правительстве РФ (сначала — главный корпус, Ленинградский
проспект, 49). Для студентов (найти, где позаниматься) и преподавателей
(найти место для внеучебной активности).

## Где искать контекст перед работой

Ресёрч уже проведён, повторять его не нужно. Перед реализацией смотри:
- `docs/01-research-summary.md` — общая картина и выводы
- `docs/02-data-sources.md` — технические детали источников данных
- `docs/03-legal-risks.md` — что можно и что рискованно
- `docs/04-architecture-mvp.md` — предложенная механика и план MVP

## Ключевые технические факты

- Источник расписания: `ruz.fa.ru` — открыт без обязательной авторизации,
  поиск по группе и преподавателю. Прямого поиска по аудитории нет — нужно
  строить обратный индекс самостоятельно (пройтись по группам, собрать
  поле аудитории/корпуса из каждой пары в их расписании).
- Готовая стартовая точка: библиотека
  [fa_api](https://github.com/GeorgiyDemo/fa_api) (GPLv3, пакет `fa-api`
  на PyPI) — умеет искать группу/преподавателя и получать расписание без
  авторизации. Перед тем как писать свой клиент с нуля, стоит посмотреть,
  подходит ли структура её ответа (есть ли в ней поле аудитории/корпуса на
  каждую пару) — это первое, что стоит проверить руками.
- Стороннее приложение «Кампус» (campusapp.ru/fu, ООО «Матклаб»,
  ed-club.ru) уже подключено к Финансовому университету и тянет расписание
  «из официальных источников». Это не источник данных для нас (нет
  открытого API, доступ — по договорённости с разработчиками), но
  подтверждение, что автоматический сбор расписания ФУ уже кем-то легально
  делается.
- Справочника аудиторий (номер/этаж/корпус/вместимость) в открытом виде не
  найдено — придётся собирать вручную (пройтись по зданию) или строить из
  фактических значений поля «аудитория», которые встретятся в выгрузках
  расписания (неполно, но достаточно для MVP).
- У вуза отдельно существует процедура бронирования аудиторий под
  мероприятия/экзамены вне расписания пар — она не интегрирована с
  `ruz.fa.ru`. Из-за этого сервис будет иногда ошибочно показывать
  «свободно», когда кабинет реально занят. Нужно либо явно предупреждать
  об этом пользователя, либо со временем закрыть через партнёрство с
  вузом или пользовательскую обратную связь («отметить как занято»).

## Ограничения, которые нужно соблюдать

- Не тянуть расписание «оптом» за весь семестр по всем группам без нужды —
  юридический риск по ст. 1334 ГК РФ (право на базу данных), см.
  `docs/03-legal-risks.md`. Забирать данные на актуальный день/неделю, не
  архивировать вузовскую базу целиком.
- Не использовать логин/пароль личного кабинета студента (`org.fa.ru`) для
  парсинга — открытого источника (`ruz.fa.ru`) достаточно, не нужно
  создавать риски, связанные с чужими учётными данными.
- Не оформлять сервис как официальный продукт Финансового университета
  (логотип/название вуза) без согласования — риск по товарному знаку.
- MVP держать узким: один корпус, ручная сверка кабинетов, без публичного
  анонса до проверки спроса.

## Язык и стиль

Пользователь ведёт проект на русском языке. Комментарии в коде, коммиты и
документация — предпочтительно тоже на русском, если не оговорено иное.
