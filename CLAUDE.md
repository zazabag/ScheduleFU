# Контекст проекта ScheduleFU

Этот файл читается Claude Code автоматически при работе в этой папке.

## Что это за проект

ScheduleFU — собственный сервис расписания Финансового университета при
Правительстве РФ. Неофициальный: администрация вуза в проекте не участвует
и о нём не знает.

Задача шире, чем «найти свободную аудиторию»: это замена `ruz.fa.ru` с
человеческим интерфейсом, где свободные аудитории — одна из функций,
которой у оригинала нет вовсе.

Функции (все только читающие):

- расписание группы;
- расписание преподавателя, в том числе «где преподаватель сейчас» —
  этим пользуются и студенты, и сами преподаватели;
- свободные аудитории на текущий момент;
- уведомления об изменениях расписания;
- экспорт во внешний календарь.

Автор делает проект для себя и хочет сделать его хорошо. Распространение
и продажа возможны, но целью не являются.

## Стек

- **Go** — весь рабочий код. Выбран автором.
- **PostgreSQL** — хранилище слепков расписания.
- **Python** — только разовые скрипты сбора справочников в `tools/`.
  В рабочий контур не входит.

## Ключевые технические факты

Источник — `ruz.fa.ru`, Laravel, чистый JSON, без авторизации. Все три
обратных индекса **уже существуют на стороне вуза**, строить их самим не
нужно:

```
GET /api/search?term={строка}&type={group|lecturer|auditorium}  -> числовой id
GET /api/schedule/{group|lecturer|auditorium}/{id}?start=&finish=&lng=1
```

- **Обход по аудиториям даёт всё сразу.** В каждой паре есть аудитория,
  время, группа (`stream`), преподаватель (`lecturerOid`) и дисциплина.
  773 запроса — полный слепок расписания всего вуза за период; расписания
  групп и преподавателей строятся из него локально.
- **Ловушка с преподавателем.** Ключ — только числовой `lecturerOid` из
  `type=lecturer`. Запрос `/api/schedule/lecturer/{GUID}` не падает, а
  возвращает сотни чужих пар с пустым полем `lecturer`. `type=person`
  отдаёт именно такой непригодный GUID. В `internal/ruz` это закрыто
  типами: `SearchPerson` намеренно не объявлен.
- **`lessonOid` стабилен** между выгрузками — по нему ищутся изменения.
  Есть и `modifieddate`: видно, когда деканат правил пару.
- **Этаж вычисляется из номера**, потому что `auditoriumfloor` всегда `0`.
  Правила разные в каждом корпусе: на 49/2 и 55 — первая цифра из трёх,
  на 51-м — вторая из четырёх с ведущим нулём. Где нумерация не
  подтверждена, этаж остаётся неизвестным и **не угадывается**.
- **Вместимость** приходит только вместе с парой, поэтому у пустующих
  аудиторий её нет (известна у 438 из 773).
- **В данных есть мусор**: `Без аудитории`, `д.а.`, `тест`, а также 119
  «помещений, не принадлежащих университету» и ~100 спортзалов. Отсев —
  в `internal/ruz` (`IsReal`, `IsStudySpace`).

## Продуктовые решения

- **Ленинградские 49, 51 и 55 — один кампус**, а не четыре адреса:
  физически это одно место с внутренними переходами. Вместе 103
  аудитории — крупнейшая площадка вуза. В источнике связи между этими
  адресами нет, склейка живёт в нашем коде.
- Ограничивать проект одним корпусом **не надо**: занятия рассеяны по 25
  адресам, и на любом отдельно взятом их меньшинство.
- **Навигация без логинов и паролей.** Человек находит свою группу
  поиском по названию, она запоминается в браузере — как на портале
  колледжа автора. Каскад «курс → факультет → направление» возможен
  позже: API отдаёт только числовой oid факультета без названия, таблицу
  расшифровок придётся вписать вручную.
- **Курс** выводится из года в названии группы (`ПИ24-1` → набор 2024).

## Ограничения, которые нужно соблюдать

- **Вежливость к чужому серверу.** Ограничение частоты, экспоненциальные
  повторы, честный `User-Agent` с контактом. Мы ходим в инфраструктуру,
  которая нам ничего не должна: лучше собирать слепок дольше, чем поймать
  бан по адресу.
- **Не тянуть расписание оптом за весь семестр.** Забираем актуальный
  день/неделю, не архивируем вузовскую базу целиком — риск по ст. 1334 ГК
  РФ, см. `docs/03-legal-risks.md`.
- **Не использовать личный кабинет `org.fa.ru`** и чужие учётные данные:
  открытого источника достаточно.
- **Не оформлять сервис как официальный продукт вуза** (логотип,
  название) без согласования — риск по товарному знаку.
- **Функцию «где преподаватель сейчас» нужно уметь отключить.** Данные
  публичные, но агрегированный ответ о местонахождении человека — не то
  же самое, что расписание группы; при распространении вопросы возникнут
  к ней первой.

## Заимствования из проекта колледжа

У автора есть боевая система расписания колледжа — Planovo KEMS
(`/Users/macintosheesh/Documents/Claude/Projects/КЭМС/ScheduleKEMS`,
Django + React, работает в проде). **Код оттуда не копируется**, переносятся
только решения.

Важно понимать разницу: KEMS — источник истины, там учебная часть сама
составляет расписание, отсюда конструктор, версии и валидация конфликтов.
ScheduleFU — зеркало внешнего источника, только чтение. Поэтому конструктор,
версии, валидация, заявки преподавателей и импорт Excel здесь неприменимы.

Полезны как ориентир: модель кабинета, устройство уведомлений
(событие → подписка → доставка через outbox), дизайн-система.
Интеграции с календарями в KEMS нет — её придётся писать с нуля.
