# Контекст проекта ScheduleFU

Этот файл читается Claude Code автоматически при работе в этой папке.

## Что это за проект

ScheduleFU — собственный сервис расписания Финансового университета при
Правительстве РФ. Неофициальный: администрация вуза в проекте не участвует
и о нём не знает.

Задача шире, чем «найти свободную аудиторию»: это замена `ruz.fa.ru` с
человеческим интерфейсом, где свободные аудитории — одна из функций,
которой у оригинала нет вовсе.

Функции (все только читающие):

- расписание группы;
- расписание преподавателя, в том числе «где преподаватель сейчас» —
  этим пользуются и студенты, и сами преподаватели;
- свободные аудитории на текущий момент;
- уведомления об изменениях расписания;
- экспорт во внешний календарь.

Автор делает проект для себя и хочет сделать его хорошо. Распространение
и продажа возможны, но целью не являются.

## Архитектура — канон

**[`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) — обязательное чтение перед
любым изменением структуры**, добавлением модуля, таблицы, зависимости или
ручки API. Там: слои и модули, правила зависимостей, владельцы таблиц,
стадии API, стыковка с Akeda ERP, план перехода от текущего кода.

Коротко, чтобы не открывать при мелкой правке:

- модульный монолит, один бинарник `schedulefu` с подкомандами;
- слои `presentation → modules → platform`, обратных рёбер нет;
- модуль говорит с модулем только через порт (интерфейс у вызывающего,
  реализация у владельца, связывание в `cmd/schedulefu`);
- у таблицы один писатель — модуль-владелец;
- миграции — `YYYYMMDDHHMMSS_описание.sql` из `date -u`, попавшая в `main`
  неизменяема;
- зависимостей вне стандартной библиотеки три: `pgx`, `webpush-go`,
  `yaml.v3`; новая — с объяснением в PR.

Проект стыкуется с Akeda ERP автора: тот же язык, те же соглашения о
модулях и миграциях, те же стадии API. HTTP-фреймворк и DI намеренно
**не** совпадают — `net/http` вместо Fiber, явная композиция вместо fx;
причины в § 4 канона, заново не обсуждаются.

## Стек

- **Go** — весь рабочий код; `net/http`, `log/slog`, `pgx/v5`.
- **PostgreSQL** — хранилище слепков расписания.
- **Python** — только разовые скрипты сбора справочников в `tools/`.
  В рабочий контур не входит.

## Ключевые технические факты

Источник — `ruz.fa.ru`, Laravel, чистый JSON, без авторизации. Все три
обратных индекса **уже существуют на стороне вуза**, строить их самим не
нужно:

```
GET /api/search?term={строка}&type={group|lecturer|auditorium}  -> числовой id
GET /api/schedule/{group|lecturer|auditorium}/{id}?start=&finish=&lng=1
```

- **Обход по аудиториям даёт всё сразу.** В каждой паре есть аудитория,
  время, группа (`stream`), преподаватель (`lecturerOid`) и дисциплина.
  773 запроса — полный слепок расписания всего вуза за период; расписания
  групп и преподавателей строятся из него локально.
- **Ловушка с преподавателем.** Ключ — только числовой `lecturerOid` из
  `type=lecturer`. Запрос `/api/schedule/lecturer/{GUID}` не падает, а
  возвращает сотни чужих пар с пустым полем `lecturer`. `type=person`
  отдаёт именно такой непригодный GUID. В `internal/ruz` это закрыто
  типами: `SearchPerson` намеренно не объявлен.
- **Языковые подгруппы — отдельные «группы» источника.** Пара английского
  приходит с `group` вида `006073_2 Иностранный язык (КАЯиПК)-10 СОЦ25-6_7`
  и пустым `stream`; базовые группы зашиты в хвост имени (`СОЦ25-6_7` —
  это СОЦ25-6 и СОЦ25-7), номер подгруппы — в `(…)-10`. Так же это
  выглядит и в расписании самой группы у вуза. Разбор — `ParseStream` и
  `subgroupOf` в `internal/modules/schedule/convert.go`; потоки без хвоста
  («…(КАЯиПК)-17») к группе привязать нельзя, и мы не угадываем.
- **`lessonOid` стабилен** между выгрузками — по нему ищутся изменения.
  Есть и `modifieddate`: видно, когда деканат правил пару.
- **Этаж вычисляется из номера**, потому что `auditoriumfloor` всегда `0`.
  Правила разные в каждом корпусе: на 49/2 и 55 — первая цифра из трёх,
  на 51-м — вторая из четырёх с ведущим нулём. Где нумерация не
  подтверждена, этаж остаётся неизвестным и **не угадывается**.
- **Вместимость** приходит только вместе с парой, поэтому у пустующих
  аудиторий её нет (известна у 438 из 773).
- **В данных есть мусор**: `Без аудитории`, `д.а.`, `тест`, а также 119
  «помещений, не принадлежащих университету» и ~100 спортзалов. Отсев —
  в `internal/ruz` (`IsReal`, `IsStudySpace`).

## Продуктовые решения

- **Ленинградские 49, 51 и 55 — один кампус**, а не четыре адреса:
  физически это одно место с внутренними переходами. Вместе 103
  аудитории — крупнейшая площадка вуза. В источнике связи между этими
  адресами нет, склейка живёт в нашем коде.
- Ограничивать проект одним корпусом **не надо**: занятия рассеяны по 25
  адресам, и на любом отдельно взятом их меньшинство.
- **Навигация без логинов и паролей.** Человек находит свою группу
  поиском по названию, она запоминается в браузере — как на портале
  колледжа автора. Каскад «курс → факультет → направление» возможен
  позже: API отдаёт только числовой oid факультета без названия, таблицу
  расшифровок придётся вписать вручную.
- **Курс** выводится из года в названии группы (`ПИ24-1` → набор 2024),
  с поправкой на то, что учебный год начинается в сентябре.
- **Филиалы в других городах** (Пенза, Челябинск, Омск и ещё десяток)
  исключены из выдачи: студенту, ищущему, где сесть между парами, дойти
  до них невозможно, а переключатель они занимали целиком.
- **Сетка занятий — восемь пар**, с 08:30 до 22:00, включая вечерние 18:55
  и 20:30: на них приходится больше двух тысяч занятий в неделю. Занятость
  слота считается по пересечению интервалов, а не по времени начала —
  около двух процентов пар идут вне сетки, вплоть до 08:00—22:00.
- **Площадка (`site`), а не `campus`, — ключ фильтрации.** `campus`
  отвечает только на вопрос «Ленинградский или нет», и все прочие адреса
  в нём одинаковы: фильтр по нему показывал двенадцать зданий вперемешку.
- **Каркас один, оформлений восемь.** Разделы, порядок блоков и места
  кнопок одинаковы везде (`base.css`, шаблоны); оформление — только CSS в
  `skins/<id>.css` плюс переменные. Выбор оформления и темы (светлая,
  тёмная, системная) — в настройках, живёт в cookie. Новое оформление —
  новый файл и строка в `web.Skins`, шаблоны не трогаются. «Герой» экрана
  дня отдаёт всем одни данные (текущая пара, фраза, маршрут, план,
  прогресс) — каждое оформление показывает из них своё.
- **Несколько пар в одном слоте — одна карточка-стопка** (`stackSlots`):
  подгруппы английского или дисциплины на выбор. Сверху общее — дисциплина
  и «3 подгруппы», по касанию раскрываются варианты с подгруппой,
  преподавателем и аудиторией. Пустой день показывает ближайший день с
  парами: в этой неделе, иначе одним запросом — в следующей.
- **Экран дня листается по дням и неделям**: полоса из семи дней, стрелки
  недели, «сегодня», свайп на телефоне. Статусы пар — прошла · сейчас ·
  следующая · позже; «сейчас» бывает только сегодня. В стенде `dev` есть
  `?now=ЧЧ:ММ`, чтобы увидеть состояние «пара идёт», не дожидаясь пары.
- **«Моё расписание» — одна сущность с двумя видами** (`internal/web`,
  `Subject`): клиентом может быть и студент, и преподаватель. Закрепление
  хранится в cookie и кодируется процентами — в cookie допустим только
  ASCII, иначе «Ю24-5» превращается в «24-5».
- **Уведомления группируются по адресату.** За проход находятся сотни
  правок; одно сообщение с итогом на каждое отслеживаемое расписание, а
  не по уведомлению на изменение.
- **Адреса статики несут отпечаток содержимого** (`asset "style.css"`):
  кэш держится год, а при изменении файла меняется адрес. Страницы,
  наоборот, некэшируемы — они отвечают «что свободно сейчас».
- **Первое наполнение базы не журналируется**: когда за период нет ни
  одной пары, а источник принёс тысячи, это не правка вуза, а появление
  данных у нас. Журнал живёт месяц, очередь уведомлений — неделю.
- **Инлайновые стили в шаблонах запрещены** политикой безопасности:
  правила живут в `style.css`, атрибут `style` ломает вёрстку молча.
- **Русские даты пишутся своей таблицей месяцев.** Раскладка `time.Format`
  понимает только английские названия: строка «2 января» печатает слово
  «января» буквально, и любая дата выглядела бы январской.

## Ограничения, которые нужно соблюдать

- **Вежливость к чужому серверу.** Ограничение частоты, экспоненциальные
  повторы, честный `User-Agent` с контактом. Мы ходим в инфраструктуру,
  которая нам ничего не должна: лучше собирать слепок дольше, чем поймать
  бан по адресу.
- **Не тянуть расписание оптом за весь семестр.** Забираем актуальный
  день/неделю, не архивируем вузовскую базу целиком — риск по ст. 1334 ГК
  РФ, см. `docs/03-legal-risks.md`.
- **Не использовать личный кабинет `org.fa.ru`** и чужие учётные данные:
  открытого источника достаточно.
- **Не оформлять сервис как официальный продукт вуза** (логотип,
  название) без согласования — риск по товарному знаку. Исключение по
  решению автора (21.09.2026): маскот-манул вуза взят как есть, с картинки вуза,
  только вырезан фон (`static/manul.webp`) — автор сообщил, что
  использование согласовано.
- **Функцию «где преподаватель сейчас» нужно уметь отключить.** Данные
  публичные, но агрегированный ответ о местонахождении человека — не то
  же самое, что расписание группы; при распространении вопросы возникнут
  к ней первой.

## Заимствования из проекта колледжа

У автора есть боевая система расписания колледжа — Planovo KEMS
(`/Users/macintosheesh/Documents/Claude/Projects/КЭМС/ScheduleKEMS`,
Django + React, работает в проде). **Код оттуда не копируется**, переносятся
только решения.

Важно понимать разницу: KEMS — источник истины, там учебная часть сама
составляет расписание, отсюда конструктор, версии и валидация конфликтов.
ScheduleFU — зеркало внешнего источника, только чтение. Поэтому конструктор,
версии, валидация, заявки преподавателей и импорт Excel здесь неприменимы.

Полезны как ориентир: модель кабинета, устройство уведомлений
(событие → подписка → доставка через outbox), дизайн-система.
Интеграции с календарями в KEMS нет — её придётся писать с нуля.

## Как мы работаем

- **Замер до оптимизации.** «Стало быстрее» — только с цифрами до и после.
- **Тест на найденный баг — до исправления**, назван по-русски тем, что
  закрепляет.
- **Ошибку в собственном выводе называть сразу**, в том же сообщении, без
  отдельной церемонии.
- **Данные источника чужие и недоверенные**: экранируются везде, политика
  безопасности не ослабляется ради удобства.
- **Тесты с базой — на настоящем PostgreSQL**, своя тестовая база на пакет:
  `go test` гоняет пакеты параллельно, на общей базе они роняют друг друга.
- **Коммит объясняет причину**, а не перечисляет файлы.
