# Модуль notes: запись пары, конспект, домашние задания

Принято 22.09.2026. Документ объясняет, почему модуль устроен так, и
фиксирует три расхождения с каноном, на которые он пошёл сознательно.

## 0. Что делает

Студент открывает раздел «Пары», выбирает предмет, нажимает «Записать» или
приносит готовый файл. Запись уезжает на сервер по ходу занятия, там
расшифровывается и превращается в конспект: тема, главные тезисы, связный
текст и отдельно — домашнее задание. Конспект и задание сохраняются по
кнопке и ложатся к предмету с датой пары.

Чем это **не** является: общей базой конспектов. Конспект виден только
своему устройству, обмена между студентами нет. Причина не техническая, см.
§ 5.

## 1. Почему предмет, а не пара

Единица раздела — предмет («История»), а не отдельная пара. Студент помнит,
что ищет конспект по истории, а не конспект пары от 18 сентября.

Отсюда же следует главное решение схемы: **связи с `lessons` нет**.
Таблица `lessons` хранит окно сбора в неделю и чистится каждым проходом
(ARCHITECTURE.md § 5) — внешний ключ унёс бы конспект вместе с парой через
семь дней. Поэтому каждая запись несёт собственный слепок пары
(`domain.LessonRef`): дисциплина, дата, время, преподаватель, аудитория.
`lesson_oid` сохраняется справочно и ключом не является.

Побочная выгода — юридическая: конспект, написанный по записи занятия, это
производное произведение пользователя, а не копия расписания вуза
([03-legal-risks.md](03-legal-risks.md) § 2).

Список предметов склеивается из двух источников: расписание даёт те, что
идут на этой неделе, наши таблицы — те, по которым уже есть конспекты.
Второе обязательно: окно расписания — неделя, а конспект нужен к сессии.

## 2. Инфраструктура: куски, очередь, отдельная служба

Пара идёт полтора часа. Из этого следует всё устройство приёма.

**Запись едет кусками по ходу занятия**, а не одним файлом в конце.
Браузер на телефоне закрывают, выгружают из памяти и теряют сеть; разница
между «потеряли минуту» и «потеряли лекцию» — вот эта. Клиент режет поток
`MediaRecorder` по пятнадцать секунд и шлёт куски строго по порядку
(`PUT /api/v1/notes/recordings/{id}/chunks/{seq}`), сервер дописывает их в
один файл. Повтор уже принятого куска отбрасывается: обрыв связи после
записи, но до ответа — обычное дело.

**Обработка — очередь в базе**, как у уведомлений: `SELECT … FOR UPDATE
SKIP LOCKED`, счётчик попыток, `next_attempt_at`. Взятая в работу строка
получает срок в час: если воркер умер посреди расшифровки, запись вернётся
в очередь, а не зависнет навсегда.

**Воркер — отдельная служба** (`schedulefu notes`), а не горутина внутри
`serve`. Расшифровка занимает все ядра на десяток минут, и страницы рядом с
ней начинают отвечать секундами. Служб стало три: `serve`, `collect`,
`notes`; разносить их по машинам теперь можно.

Путь записи целиком:

```
браузер ──куски──▶ recordings (uploading)
                        │ finish
                        ▼
                    queued ──▶ ffmpeg: WAV 16 кГц моно ──▶ decoding
                        ▼
              sherpa-onnx + GigaAM v3 ──▶ transcribing ──▶ расшифровка в базу
                        ▼                                  (аудио удаляется)
              чат-модель по HTTP ──▶ summarizing ──▶ конспект + задания (черновики)
                        ▼
                      ready
```

## 3. Распознавание: GigaAM v3 на своём сервере

| | Выбор | Почему |
|---|---|---|
| Модель | [GigaAM v3](https://github.com/salute-developers/GigaAM) (MIT, 240M) | лучший открытый русский ASR: v2 уже давала около половины относительного выигрыша к Whisper large-v3 на русском, v3 — ещё 30 % на новых доменах |
| Среда | [sherpa-onnx](https://k2-fsa.github.io/sherpa/onnx/) (Apache-2.0), [готовые модели](https://huggingface.co/csukuangfj/sherpa-onnx-nemo-transducer-giga-am-v3-russian-2025-12-16) | C++, никакого Python в рабочем контуре (`CLAUDE.md`), никакого GPU: int8 на CPU даёт порядка 10–20× реального времени, пара считается 5–15 минут |
| Как зовём | внешним процессом, не через cgo | связывать бинарник с onnxruntime — тянуть сборку C++ в деплой ради вызова, который и так длится минуты; процесс падает отдельно от сервера |
| Подготовка звука | ffmpeg | браузеры пишут webm/opus и mp4/aac, диктофон приносит m4a; декодеров полудюжины форматов в стандартной библиотеке нет |

Главное, что даёт своя модель, — **аудио не покидает наш сервер**. Это
снимает разом и трансграничную передачу голоса преподавателя, и плату за
минуты: облачное распознавание обошлось бы примерно в 54 ₽ за пару, то есть
около тысячи рублей в неделю на активного студента.

Разбор вывода распознавателя намеренно терпимый (`asr.Parse`): сборки
печатают то JSON, то «0.000 -- 5.120 текст», то голую строку. Обновление
бинарника не должно молча превращать конспект в пустую страницу.

## 4. Конспект: чат-модель по HTTP

Порт `Summarizer` реализован одним адаптером для любого сервиса в стиле
OpenAI (`POST /chat/completions`). GLM, GigaChat, OpenRouter, локальная
модель — это адрес, ключ и имя модели, то есть три строки конфига.

По умолчанию — GLM-4.6: 200k контекста, то есть полуторачасовая пара
(~30 000 токенов) обрабатывается **одним запросом**. Если модель с окном
поменьше, текст режется на части по концу предложения, каждая
пересказывается, и второй проход пишет конспект по пересказам.

Что уходит наружу: дисциплина, дата, длительность и расшифровка. **Имени
преподавателя и группы в запросе нет** — они остаются в нашем слепке пары.
Расшифровка всё же уезжает к чужому сервису, и это осознанная плата за
бесплатный конспект; переключение на российский сервис — строка в конфиге.

Расшифровка в промпте помечена как данные, а не указания: в аудитории
звучит всякое, и «а теперь забудь всё, что я говорил» модель не должна
принимать на свой счёт.

Ответ разбирается терпимо: просить JSON и получать JSON — разные вещи,
модель добавляет вступление и обрамление кодом.

## 5. Юридическая рамка и что из неё следует в коде

Запись занятия — не нейтральное действие. Лекция охраняется авторским
правом (ст. 1259 ГК), голос преподавателя — персональные данные, а запись
для себя допустима как свободное воспроизведение в личных целях (ст. 1273
ГК). Это ровно та рамка, в которой раздел работает, и она задаёт четыре
решения:

1. **Аудио удаляется сразу** после расшифровки. Остаётся текст: по нему
   можно пересобрать конспект, не заставляя записывать пару заново.
   `keep_audio` в конфиге есть, по умолчанию выключен.
2. **Конспекты приватные**, обмена нет. Как только конспект лекции
   расходится по курсу, «личные цели» кончаются.
3. **Имена наружу не уходят** (§ 4).
4. **Предупреждение на экране записи**, а не в настройках — тем же тоном,
   что предупреждение про внерасписные брони.

Отдельно: распространять сервис с этим разделом стоит уже после разговора с
вузом ([05-roadmap.md](05-roadmap.md), этап 3). Раздел «где преподаватель
сейчас» вызовет вопросы первым, запись занятий — вторым.

## 6. Фон: чего PWA не умеет

Честная граница, которую надо знать до того, как студент понадеется на
приложение посреди пары.

- **Android, Chrome**: запись переживает сворачивание и гаснущий экран;
  Wake Lock держит экран, куски продолжают уезжать.
- **iOS, PWA с рабочего стола**: не переживает. Safari усыпляет страницу
  вместе с экраном, и запись обрывается. Wake Lock в установленном PWA
  чинили до iOS 18.4, и даже он не спасает при сворачивании.

Поэтому «Загрузить файл» — не запасной путь, а основной для айфона: пара
пишется штатным диктофоном, файл приносится в раздел обычной формой, и она
работает без скрипта вовсе. Кнопка записи появляется только там, где
браузер её тянет.

Нативное приложение это бы решило, но канон (§ 9) их не предусматривает, и
ради одной функции решение не переигрывается.

## 7. Три расхождения с каноном

Записаны здесь, потому что канон требует объяснять, а не обходить молча.

| Что в каноне | Что сделано | Почему |
|---|---|---|
| «`web` — серверный рендеринг, JS только для подписки» (§ 3.5) | второй скрипт, `record.js` | запись с микрофона без MediaRecorder невозможна. Скрипт остаётся необязательным: без него работает всё, кроме записи в приложении |
| «нет аккаунтов» (§ 0) | ключ владельца в cookie | конспект обязан кому-то принадлежать, иначе его видит любой. Это не аккаунт: случайные 16 байт, ни почты, ни пароля, узнать человека по ключу нельзя. Канон (§ 9) допускает «аккаунт без пароля, если попросят» — это он и есть, в самой дешёвой форме |
| три зависимости вне стандартной библиотеки (§ 4) | их по-прежнему три | ни одной новой: HTTP к модели — `net/http`, JSON — стандартный, распознавание и ffmpeg — внешние процессы |

Плюс одна правка платформы: `Permissions-Policy` пускает микрофон своим
страницам (`microphone=(self)`). Без этой строки браузер не спросит
разрешения вовсе. CSP не ослаблена.

## 8. Настройка

```yaml
notes:
  enabled: true
  audio_dir: /var/lib/schedulefu/audio
  max_minutes: 240        # потолок на запись; пара — 90
  max_mb: 512
  keep_audio: false       # включать только осознанно
  ffmpeg: ffmpeg
  asr:
    command: sherpa-onnx-vad-with-offline-asr
    model_dir: /var/lib/schedulefu/models/gigaam-v3
    threads: 4
  llm:
    base_url: https://api.z.ai/api/paas/v4
    model: glm-4.6
    max_chars: 240000
  worker:
    idle: 20s
    retry: 10m
    attempts: 3
    draft_days: 14
```

Ключ модели — только в окружении: `SCHEDULEFU_NOTES_LLM_API_KEY`.

Модель распознавания кладётся руками:

```bash
mkdir -p /var/lib/schedulefu/models/gigaam-v3
# encoder.int8.onnx, decoder.int8.onnx, joiner.int8.onnx, tokens.txt, silero_vad.onnx
```

Имена файлов и флаги у разных сборок sherpa-onnx расходятся; если сборка
другая, командная строка задаётся целиком через `asr.args` с подстановками
`{wav}`, `{models}`, `{threads}` — менять её в конфиге правильнее, чем в
коде.

Раздел показывается, пока `notes.enabled`; принимать новые записи он
начинает только когда настроено всё сразу — ffmpeg, модель распознавания и
ключ чат-модели (`Config.NotesReady`). Обещать конспект, которого не будет,
хуже, чем не предлагать запись.

## 9. Что осталось за рамками

- **Перенос конспектов на другое устройство** — экран с шестизначным кодом.
  Канон (§ 9) разрешает, но делать стоит, когда попросят.
- **Разделение говорящих**: сейчас расшифровка сплошная. Для конспекта
  этого достаточно, для семинара с обсуждением — уже нет.
- **Правка конспекта руками**: пока его можно только удалить и записать
  пару заново.
- **Поиск по конспектам** — при нескольких десятках он понадобится.
