# Сводка исследования гипотезы (сентябрь 2026)

## Вопрос

Можно ли сделать портал/сервис, показывающий свободные аудитории главного
корпуса Финансового университета (Ленинградский проспект, 49), и откуда
брать для этого достоверные данные.

## Короткий ответ

Да, технически реализуемо. Ключевой источник данных (`ruz.fa.ru`) открыт
без обязательной авторизации, под него уже существуют сторонние
библиотеки — часть работы по «оцифровке» уже сделана другими людьми.
Основные риски не технические и не уголовно-правовые, а гражданско-
правовые (право на базу данных вуза) и организационные (расхождение
расписания с реальной занятостью аудиторий из-за внерасписных
бронирований). Оба риска снимаются одним и тем же действием — открытым
диалогом с вузом вместо тихого парсинга и раздачи всем.

## Источники данных: что нашли

1. **`ruz.fa.ru`** — официальная система «Расписание учебных занятий»
   Финансового университета. Доступ к просмотру, по всем найденным
   свидетельствам, открыт без обязательной авторизации. Поиск — по группе
   и по преподавателю, с указанием периода дат. Прямого поиска по
   аудитории нет, но в ответе на запрос расписания группы почти наверняка
   есть поле аудитории/корпуса на каждую пару — значит, обратный индекс
   «аудитория → занятые слоты» можно построить самим, пройдя по всем
   группам. Подробности — `02-data-sources.md`.

2. **Готовая сторонняя библиотека `fa_api`** (GitHub, GPLv3, есть и пакет
   на PyPI под именем `fa-api`) — уже умеет искать группу/преподавателя и
   получать их расписание без авторизации. Это отличная отправная точка:
   не обязательно писать клиента к `ruz.fa.ru` с нуля.

3. **Приложение «Кампус»** (campusapp.ru/fu) — сторонний коммерческий
   продукт (ООО «Матклаб», ed-club.ru), уже подключённый к Финансовому
   университету, тянет расписание «из официальных источников». Прямым
   источником данных для нас не является (нет открытого API, доступ — по
   договорённости с разработчиками), но служит доказательством, что
   автоматический сбор расписания ФУ уже кем-то легально делается и даже
   монетизируется.

4. **Личный кабинет `org.fa.ru`** — требует логин/пароль студента,
   вероятно дублирует то же расписание, что и открытый `ruz.fa.ru`. Лезть
   туда смысла нет: то же самое доступно без чужих учётных данных, а
   значит — без сопутствующих рисков.

5. **Telegram-бот с веб-интерфейсом**, о котором упоминал пользователь —
   не выяснено, официальный он или самописный студенческий. Если
   самописный — вероятно, тоже просто зеркалит `ruz.fa.ru`, отдельным
   источником можно не считать.

6. **Слепая зона: бронирования аудиторий вне расписания пар.** У вуза
   есть отдельная процедура заявки на аудиторию для мероприятий,
   кафедральных встреч, пересдач и т. п. (см., например, «Справочник
   организатора мероприятий» на fa.ru), которая не отражена в
   `ruz.fa.ru`. Это значит, что даже идеальный парсер расписания пар будет
   иногда ошибочно показывать «свободно» там, где кабинет занят
   мероприятием. Без интеграции со второй системой (доступной только по
   договорённости с вузом) это стоит либо явно указывать пользователю,
   либо закрывать пользовательской обратной связью.

## Механика определения свободных аудиторий

1. Построить справочник аудиторий (корпус → этаж → номер → вместимость/
   тип). Готового открытого списка не нашли — собирать вручную (обход
   здания) или из фактических значений поля «аудитория» в выгрузках
   расписания.
2. Собирать расписание всех групп (и/или преподавателей) главного корпуса
   на нужный период.
3. Строить обратный индекс: аудитория → список занятых интервалов на
   дату/время.
4. Регулярно обновлять (расписание меняется задним числом — замены,
   переносы), не реже раза в 15–60 минут.
5. Явно обозначать предел точности из-за слепой зоны с бронированиями вне
   расписания.

Подробный план — `04-architecture-mvp.md`.

## Юридическая сторона

- Раз `ruz.fa.ru` открыт без обязательного логина, обхода защиты нет —
  состав ст. 272 УК РФ («неправомерный доступ») не образуется.
- Основной реальный риск — исключительное право изготовителя базы данных
  (ст. 1334 ГК РФ): систематическое «выкачивание» существенной части
  расписания вуза и republication в виде отдельного продукта может быть
  расценено как нарушение этого права, даже если каждая отдельная запись
  общедоступна. Ориентир — дело «ВКонтакте против Дабл» (систематический
  парсинг признан судом нарушением). Чем уже объём и период выгрузки
  (день/неделя, один корпус), тем ниже риск.
- При попытке автоматически обратиться к `ruz.fa.ru` получен отказ по
  правилам `robots.txt` — юридической силы это не имеет, но сигнализирует
  о нежелании вуза видеть автоматическое сканирование, и это стоит
  учитывать в переговорах, а не игнорировать.
- Использование названия/логотипа Финансового университета в оформлении
  сервиса без согласования — отдельный риск по товарному знаку, если
  сервис выглядит как официальный.

Подробности и рекомендации — `03-legal-risks.md`.

## Прецедент, о котором рассказал друг

Точного публичного описания именно этого кейса («студенты сделали и
продали вузу») найти не удалось, но обнаружен очень близкий по духу
реальный механизм: федеральная программа «Платформа университетского
технологического предпринимательства» (университетские стартап-студии,
гранты «Студенческий стартап» от Фонда содействия инновациям). Судя по
всему, именно через неё выросло то же приложение «Кампус» — тоже
студенческий по духу продукт, который затем внедрился в вузы, включая
Финансовый университет. Это рабочий, легальный путь именно к тому
сценарию, который описывал друг пользователя.

## Рекомендованный путь

1. Технический пилот на 10–20 группах — проверить своими глазами
   структуру ответа `ruz.fa.ru`/`fa_api` и наличие поля аудитории.
2. Узкий MVP на части главного корпуса, без публичного анонса — проверить
   спрос.
3. Автоматизация и расширение на весь корпус.
4. Выход на диалог с деканатом/ИТ-отделом/студсоветом с готовым
   прототипом — либо получить официальный доступ/данные, либо передать
   продукт вузу через программу поддержки студенческих стартапов.
5. Расширение на остальные корпуса — вероятно, только добавлением новых
   аудиторий в справочник, без поиска новых источников данных.

Подробный план по этапам — `05-roadmap.md`.
