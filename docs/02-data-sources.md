## 1. ruz.fa.ru — основной источник (расписание)

- **Что это.** Официальная система «Расписание учебных занятий» («РУЗ»)
  Финансового университета. Такая же система (по URL-паттерну и
  архитектуре) встречается и у других вузов: `ruz.hse.ru` (НИУ ВШЭ),
  `ruz.spbstu.ru` (СПбПУ), `ruz.narfu.ru` (САФУ), `ruz.guz.ru` (ГУЗ) —
  похоже на общую платформу, растиражированную по вузам.
- **Авторизация.** По независимым источникам — просмотр расписания
  доступен без обязательной авторизации.
- **Поиск.** По группе (например, «ПИ19-5») и по преподавателю (поиск по
  фамилии), с указанием диапазона дат.
- **Чего нет.** Прямого поиска «по аудитории» в известных обёртках не
  обнаружено. Но у каждой пары в расписании группы, вероятно, есть поле с
  аудиторией/корпусом — это нужно подтвердить, дёрнув реальный ответ API
  (см. пункт про технический пилот в `01-research-summary.md`).
- **robots.txt.** Прямой автоматический fetch страницы `ruz.fa.ru`
  блокируется правилами robots.txt инструмента веб-доступа — сигнал, что
  вуз не приветствует произвольное сканирование сайта извне (юридической
  силы не имеет, но к сведению).
- **Техподдержка.** Указан контакт `ruz@fa.ru` — потенциальная точка
  входа для официального запроса доступа/данных.

## 2. Готовая библиотека fa_api

- GitHub: https://github.com/GeorgiyDemo/fa_api
- PyPI: https://pypi.org/project/fa-api/ (пакет `fa-api`)
- Лицензия: GPLv3
- Авторизация не требуется — работает с публичными данными `ruz.fa.ru`.
- Методы: `search_group(name)`, `timetable_group(id, start_date,
  end_date)`, `search_teacher(name)`, `timetable_teacher(id, start_date,
  end_date)`.
- В README нет примеров работы с аудиториями/корпусами — но, по
  описанию автора, тот же код может использоваться и для `ruz.hse.ru`,
  значит платформа действительно общая.
- **Что сделать в первую очередь:** установить пакет, вызвать
  `timetable_group` для нескольких групп главного корпуса и посмотреть
  сырую структуру ответа — есть ли там поле аудитории/корпуса, как оно
  называется, какого формата.

## 3. Приложение «Кампус» (campusapp.ru)

- Страница именно для Финансового университета: https://campusapp.ru/fu
- Разработчик: ООО «Матклаб» (ИНН 2901313073, ОГРН 1232900001773, Москва)
- Продукт реализован при поддержке Фонда содействия инновациям в рамках
  федерального проекта «Платформа университетского технологического
  предпринимательства».
- Функционал: расписание, чат вуза («Подслушано»), оценки преподавателей,
  студенческие скидки, курсы, вакансии.
- Данные о расписании «автоматически получает из официальных источников»
  — детали интеграции не раскрыты, но, вероятно, это тот же `ruz.fa.ru`
  или прямая выгрузка от деканата.
- Открытого API для сторонних разработчиков не найдено. Контакты для
  интеграции/сотрудничества: kirill@ed-club.ru, julia@ed-club.ru,
  Telegram/ВКонтакте проекта.
- **Роль в проекте:** не источник данных, но (а) доказательство
  легальности автосбора расписания ФУ, (б) потенциальный партнёр или
  конкурент — стоит иметь в виду при выходе на диалог с вузом.

## 4. Личный кабинет org.fa.ru

- Требует логин/пароль, выданные студенту.
- Скорее всего дублирует то же расписание, что доступно открыто через
  `ruz.fa.ru`.
- **Рекомендация:** не использовать как источник — не нужно создавать
  риски, связанные с автоматизацией под чужими/личными учётными данными,
  если то же самое доступно без них.

## 5. Telegram-бот с веб-интерфейсом

- Упомянут пользователем, официальный статус не выяснен. Официальный канал
  вуза в Telegram: https://t.me/finuniverchan — стоит проверить, тот ли
  это бот, либо это отдельный студенческий проект.
- Если это сторонний (студенческий) бот — вероятно, тоже просто зеркалит
  `ruz.fa.ru`, отдельным независимым источником можно не считать.

## 6. Справочник аудиторий (не найден в открытом виде)

- Официального открытого списка аудиторного фонда (номер, этаж, корпус,
  вместимость) не обнаружено.
- Единственный намёк на существование внутреннего учёта — «Справочник
  организатора мероприятий»:
  http://www.fa.ru/org/div/oniiprs/Pages/oonm-materials.aspx — описывает
  процесс подачи заявки на аудиторию, то есть у вуза есть внутренняя
  система бронирования, не связанная с `ruz.fa.ru`.
- **Практический вывод:** справочник аудиторий придётся собирать вручную
  (обход здания на Ленинградском, 49) либо агрегировать из фактических
  значений, которые встретятся в выгрузках расписания — второе проще, но
  не покроет кабинеты, где никогда не бывает пар.

## 7. Слепая зона: бронирования вне расписания

- Экзамены, пересдачи, кафедральные мероприятия, ремонт и т. п. могут не
  отражаться в `ruz.fa.ru`, но кабинет при этом занят.
- Без доступа к системе бронирования (см. пункт 6) сервис будет иногда
  ошибочно показывать «свободно». Варианты закрытия — явный дисклеймер
  пользователю, краудсорс-обратная связь («отметить как занято»), либо
  договорённость с вузом о доступе ко второй системе.
