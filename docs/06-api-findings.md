# API ruz.fa.ru — проверено руками

Дата проверки: 12.09.2026. Этот документ имеет приоритет над
`02-data-sources.md` и `04-architecture-mvp.md` там, где они расходятся:
те написаны по результатам кабинетного ресёрча, этот — по живым ответам
сервера.

## Общее

Бэкенд — Laravel, отвечает чистым JSON, авторизация не требуется, CORS
не проверялся (не нужен: ходим со своего бэкенда). Ошибки приходят в двух
форматах: `{"error":1,"message":"..."}` для прикладных и обычная
Laravel-трассировка для несуществующих маршрутов.

## Эндпоинты

### `GET /api/search?term={строка}&type={group|auditorium}`

Строка поиска — **минимум 3 символа**, иначе `«Слишком короткая строка»`.
Отдаёт топ-N совпадений (не весь список), поэтому полный справочник
собирается только перебором префиксов.

Для `type=auditorium` в `description` лежит готовая тройка
`название | корпус | тип`, где тип — `Лекционная`, `Лаборатория`,
`Поточная`, `Коворкинг`, `Аудитория для семинарских занятий`,
`Аудитория иностранных языков`. То есть **тип и корпус не надо собирать
ногами** — вопреки `02-data-sources.md`.

### `GET /api/schedule/auditorium/{oid}?start=ГГГГ.ММ.ДД&finish=ГГГГ.ММ.ДД&lng=1`

**Расписание конкретной аудитории напрямую.** Это главная находка:
`02-data-sources.md` утверждал, что поиска по аудитории нет и обратный
индекс придётся строить самим, обходя все группы. Индекс уже есть на
стороне вуза.

Проверено: аудитория главного корпуса даёт 35–45 пар за неделю, то есть
отдаётся полная загрузка независимо от того, знаем ли мы группы.

`oid` разреженные: в проверенном диапазоне 1970–1999 живых 7 из 30.
Полный справочник собирается разовым перебором диапазона.

### `GET /api/schedule/group/{id}?start=...&finish=...&lng=1`

Расписание группы. В каждой паре есть всё нужное:

| Поле | Пример | Комментарий |
|---|---|---|
| `auditorium` | `ЛП49/2/313` | самоописывающее имя |
| `auditoriumAmount` | `54` | **вместимость** |
| `auditoriumOid` | `2851` | ключ для запроса по аудитории |
| `building` | `Ленинградский проспект, 49/2` | |
| `auditoriumfloor` | `0` | **всегда 0, бесполезно** |
| `beginLesson` / `endLesson` | `08:30` / `10:00` | |
| `date` | `2026-09-08` | |
| `discipline`, `kindOfWork`, `lecturer`, `stream`, `listOfLecturers` | | |
| `modifieddate` | | видно, когда деканат правил пару |

Из 611 полученных пар **без аудитории — ноль**. Поле заполняется всегда.

`auditoriumfloor` пустой, но этаж парсится из имени: `ЛП49/2/313` → 3-й
этаж. Ручной обход здания ради этажей не нужен.

### Чего нет

`/api/dictionary/auditorium` → «Справочник не найден».
`/api/auditoriums`, `/api/buildings` → маршрута нет.

## Производительность

| Запрос | Среднее | Максимум |
|---|---|---|
| поиск | 0.12с | 0.31с |
| расписание группы на неделю | 0.81с | 3.82с |

Разброс до 3.8с — причина держать свой кэш, а не ходить в `ruz.fa.ru`
из клиента на каждый чих.

## Неожиданное: география занятий

Выборка из 25 групп за неделю дала 152 уникальные аудитории,
распределённые так:

| Пар | Адрес |
|---|---|
| 40 | 4-й Вешняковский проезд, 4 |
| 25 | ул. Верхняя Масловка, 15 |
| 23 | ул. Щербаковская, 38 |
| 20 | Ленинградский проспект, 51, корп. 1 |
| 16 | **Ленинградский проспект, 49/2** |
| 15 | ул. Кибальчича, 1, стр. 2 |
| … | ещё 4 адреса |

**Главный корпус — не главная площадка.** Предпосылка `04-architecture-mvp.md`
и `CLAUDE.md` о том, что MVP надо ограничить Ленинградским 49, делает сервис
бесполезным для студента, который туда почти не ездит. Ограничивать надо не
корпусом, а объёмом данных (текущий день/неделя) — юридическое требование из
`03-legal-risks.md` при этом соблюдается полностью.

Отдельно: в расписании фигурирует `Ленинградский проспект, 49/2`, а не
`49` — что именно считать «главным корпусом», надо уточнить на месте.

## Следствия для архитектуры

1. Обратный индекс из `04-architecture-mvp.md` (п. 3) **не нужен** —
   выкидываем.
2. Ручной обход здания из `04-architecture-mvp.md` (п. 1) **не нужен** —
   корпус, тип, вместимость и этаж выводятся из API.
3. Сбор строится по аудиториям, а не по группам: дешевле, точнее и
   заведомо укладывается в ограничение «не тянуть базу оптом».
4. `fa_api` (GPLv3) не нужна — API тривиальный, свой клиент проще и не
   тянет в проект вирусную лицензию.
