# План функций: чем выигрываем у бота вуза

Принято 23.09.2026. Документ фиксирует, что строим после расписания и
конспектов, в каком порядке и почему. Статусы обновляются по ходу работы.

## 0. С кем соревнуемся на самом деле

Проверено по открытым источникам 23.09.2026 (ссылки — в § 7).

| | Бот «ФИН Помощник» + lk.fa.ru | ScheduleFU |
|---|---|---|
| Расписание группы, преподавателя, аудитории | есть | есть |
| Уведомления об изменениях, календарь, темы оформления | есть | есть |
| Вход для студентов **и преподавателей**, зачётка, посещаемость, пропуск | есть (lk.fa.ru, org.fa.ru) | нет и не будет: `org.fa.ru` нам закрыт каноном |
| Свободные аудитории сейчас и на любую пару | не нашли | есть |
| Окна, общие окна групп, переезды | не нашли | есть |
| Конспект пары из записи | нет | есть |

Вывод: у вуза официальные бот и кабинет, и они растут. В кабинете у вуза
преимущество, которое нам не отнять. Выигрывать надо на знании о **всём
вузе сразу** (аудитории, пересечения, кампус) и на **учебном цикле**
(пара → конспект → повторение → экзамен).

Отдельно: у бота есть режим преподавателя через единый кабинет. Сама по себе
«функция для преподавателя» нас не отличает. Отличают свободная аудитория под
консультацию и конспект собственной лекции.

## 3. Обмен конспектами

Решение автора (23.09.2026): **делиться можно без условий** — ни согласия
преподавателя, ни подтверждения почтой. Человек и так может скопировать
текст и переслать; усложнять ему жизнь незачем. Устройство и правовой фон —
в [07-notes-module.md](07-notes-module.md) § 5.

Сделано: ссылка на сохранённый конспект, страница по ссылке без ключа
устройства, «Сохранить себе» (копия с заданиями к закреплённой группе, без
дублей), «Закрыть ссылку». Дальше по желанию: лента «конспекты моей группы»
по тем же ссылкам.

## 4. Фаза 3 — личное планирование

Калькулятор баллов и учёт пропусков **не делаем**. Посещаемость уже ведёт
кабинет вуза, а порога недопуска по пропускам нет: результаты текущего
контроля недопуском не грозят (Положение 2187/о, п. 2.7), на посещение
приходится не больше 6 баллов из 100. «Поездки по вузу» тоже не делаем.

| # | Что |
|---|---|
| 3.1 | Утренняя сводка в уведомлении: сколько пар, где первая. Время выхода — по дороге, которую человек задаёт один раз |
| 3.2 | Пометки к паре («контрольная», «взять калькулятор»): видны на карточке пары, напоминание накануне |
| 3.3 | Режим сессии: экзамены и консультации из источника, обратный отсчёт |
| 3.4 | Прогресс семестра: неделя N из M, чётная или нечётная |

**Экран-статус.** Живой экран, который хочется снять на телефон: манул,
группа и курс, «день 23 учебного года», текущая пара, пульс вуза («сейчас
идёт 412 пар, свободно 61 аудитория»), цвет по времени суток. Кнопка
«сохранить картинку 9:16» для сторис. Сезонные версии: первый день года,
сессия, последняя пара семестра. Два ограничения:

- **Не похож на студенческий билет или пропуск**: ни фото, ни ФИО, ни
  номера, ни герба. Похожее на документ — это уже не тренд, а статья УК о
  подделке документов.
- Логотипа вуза нет (риск по товарному знаку, `CLAUDE.md`), манул есть: его
  использование согласовано.

Итоги семестра требуют истории, а сырые пары мы не храним (канон § 5).
Поэтому с начала семестра копятся только **агрегаты на расписание**: пар за
неделю, часы по площадкам, самая частая аудитория. Это разрешённая канону
форма (§ 9, «агрегаты без сырых пар»).

## 6. Фаза 5 — план кампуса

Решение автора (23.09.2026): **3D не делаем**, ограничиваемся планом.

Первая попытка — восстановить места аудиторий по схемам мероприятия вуза,
где подписано лишь девять, — дала перекошенный план, на котором больше
догадок, чем знания. Отказались. Теперь правило одно: **на плане только то,
что известно наверняка**.

**Сделано.** Модуль `campus`, экран `/map`:

- настоящие контуры корпусов Ленинградского кампуса из OpenStreetMap
  (49 и 49/2, 51 к.1–к.3, 51 с.4, 53, 55) в формате Apple IMDF
  (`internal/modules/campus/plans/leningradsky.geojson`, собирает
  `tools/plans/osm.py`); ссылка на OSM под планом — требование ODbL;
- номер аудитории в расписании ведёт на план: выделен корпус и этаж, под
  планом — аудитории этого этажа из справочника расписания;
- переходы между корпусами — только подтверждённые схемами вуза (49/2 ↔
  51 к.1 на 3 этаже).

Где аудитория **на этаже**, план пока не показывает: внутренних планов в
открытом доступе нет (в OSM внутри корпусов пусто, в паспортах доступности
планов нет).

**Дальше, если на этажах есть планы эвакуации.** Фото каждого этажа →
обводка в QGIS по контуру корпуса из OSM (помещение — прямоугольник с
номером) → `unit` в том же IMDF-файле → экран рисует помещения. Проверка
автоматическая: каждый номер на плане должен быть в расписании, этаж из
номера — совпадать с этажом плана. Девять аудиторий, подписанных на
схемах вуза, — контрольные точки обводки. Оценка — 30–90 минут на этаж.
Потом — маршрут по графу коридоров.
